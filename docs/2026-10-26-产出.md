## 二、今日最硬的部分：WorkBuddy 桌面端桥接

### 卡点不在选择器，在输入

CDP 连上后 `Input.insertText` 和 `Input.dispatchKeyEvent` **完全无效**——窗口提到前台也没用。
往下试了三层都不行：

| 尝试 | 结果 |
|---|---|
| CDP `Input.insertText` / `dispatchKeyEvent` | 静默无效（前台焦点下同样） |
| 页面内 `execCommand('insertText')` | DOM 变了，React state 不动，发送按钮仍 disabled |
| 取 `__reactFiber$` 里的 Slate editor 实例改 `children` | 内部值变了，判「有无内容」的是另一层 state |
| 直调 `.cr-send-button` 的 React `onClick` | 有内容守卫，直接返回 |

**对照组**：豆包桥接用的正是 `Input.insertText`，一直正常 → 不是 CDP 的问题，是 WorkBuddy 这个构建禁的。

### 解法：降到 OS 级

新增 `backend/app/wb_input.py`（纯 `ctypes`，零第三方依赖）：

- DPI 感知（`PER_MONITOR_AWARE_V2`），坐标 = `(screenX + rect.x) * devicePixelRatio`
- 点击：`SetCursorPos` + `SendInput` 鼠标事件
- 键盘：`keybd_event` 发真实 VK 码（`KEYEVENTF_UNICODE` 实测无效）
- 中文/换行：写系统剪贴板 + `Ctrl+V`
- 清空：`Ctrl+A` + `Delete`

### 回读的两个坑

1. 让模型输出哨兵 `⟦END⟧` 判定完成 → 哨兵字符串必须写在 prompt 里教它，
   于是用户消息里也有，回读时误判完成、把 prompt 当答案返回。
2. 改用按钮状态 `--sending` → 生成中会短暂闪烁，抓到中间态「深度思考中」。

现方案：prompt 末尾放独有分隔符 `⟪PROMPT-END⟫`，回答区 = 分隔符之后；
完成判定看 UI 的「已完成 Ns」；`_clean_answer()` 剥掉状态行与用量统计。

## 四、顺手修掉的自愈问题

查「重启后能否自动重连」时发现三处会主动把状态搞坏：

1. **启动 seed 把桥接成员打回不可用并踢出团队**
   `health == "unavailable"` 就强制覆盖 + `in_team=0`。对 CDP 桥接类是灾难。
   修：新增 `LIVE_PROBE`，这四类跳过强制覆盖，且不再动 `in_team`。
2. **派活遇到不可用执行体会留僵尸 running**
   `if has_real_runner: launch()` 没有 else → 任务停在进度 0，谁也没动。
   修：返回 `degraded:true` + 原因，任务退回 pending。
3. **后端重启后 running 任务无人回收**
   修：`reclaim_running()` 在 lifespan 统一回收。

新增 `probe.py`（统一探测）、`bridge_watch.py`（心跳：快档 15s / 慢档 120s）。

实测：手工把状态改成 unavailable，重启后端 **12 秒内自动恢复 online**；
状态过期时立刻派活也照样 `ok:true`。
